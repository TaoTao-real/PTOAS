# 融合 VF 与 CV 寻优的可重绑定存储接口

日期：2026-10-22
状态：proposed；受限实验实现已开始，完整验收未通过
实现及验收计划：[cv-vf-planmemory-implementation-plan.md](../designs/cv-vf-planmemory-implementation-plan.md)

2026-10-23 评审补充：受限 micro 及按 SHA 限定的固定 FA 已分别完成原生链路验证；
固定 FA 的冻结模型推荐取得 33.04% 配对降时。此结果不改变通用接口的未完成状态。
当前实现边界、代理模型误差及合入前置项见
[cost model 评审指南](../designs/cv-vf-costmodel-review-guide.md)。

## 目标

支持 cost model 评估 PTOAS 实际融合后的 VF，推荐 CV preload 和逐 Buffer
槽数。PTOAS 消费计划，执行自动内存规划、同步与合法性验证，并生成可运行代码。

用户不需要编辑输入 IR、填写地址表或调用固定 FA materializer。
支持范围内的正式验收必须使用未预设 local 地址的输入，并证明 PlanMemory 实际执行。

已验证分支的提交为 `f4df5091f7720e231f1255073cc2f9a6c9a16095`。

## 决策

### 1. 拆分存储职责

| 信息或动作 | 处理时机 |
| --- | --- |
| shape、dtype、layout、对齐、alias、ownership | VF 准备前明确 |
| VF 内部临时空间与访存效果 | VF 准备时计算并导出摘要 |
| 跨阶段 Buffer 版本、槽数和生命周期 | CV 候选生成时确定 |
| 最终物理分配和必要的复用约束 | 候选确定后由编译器完成 |
| 实际同步、临时存储及成本变化 | 最终编译反馈中核对 |

不将现有 PlanMemory 整体直接搬到低层 VF 之后。
先拆开逻辑对象分析与最终地址落实，使 PlanMemory 能分析已准备 VF 的调用效果。

VF 准备需要布局和别名条件，但不能依赖所有外部 Buffer 已有最终绝对地址。
地址敏感的转换必须记录条件；最终绑定不满足条件时，重新准备受影响 VF。

### 2. 保留可复用 VF 边界

优先使用 `func.func`/`func.call` 表达 prepared VF 及其调用。
VF 外部地址通过显式参数传入，内部访问使用相对偏移。
禁止从 SSA 名或最终数值地址反推逻辑身份。

调用契约包含：

- VF 和 stage ID、来源，以及程序指纹。
- 每个参数的逻辑 Buffer 根、类型、布局、有效范围、对齐和别名约束。
- 读、写、读改写范围，内部 scratch 需求和所属物理核。
- 依赖、迭代距离、访问完成条件与通信释放条件。
- ISA、target、unroll、调度、同步和地址敏感条件。

提供统一的 C++ VF 效果查询，供 CV 依赖分析、PlanMemory 和同步分析使用。
效果由编译器从 VF 推导并校验，不能只信任外部填入的摘要。
未知调用不能按无访存处理，也不能通过 G2。

准备后的 VF 由明确的边界保护，避免后续通用 inliner/fusion 再改变它。
若现有调用形式不能可靠表达所需效果或完成条件，先补齐类型化接口和 verifier，
再开放该输入；不能用未验证的字符串属性代替语义。

### 3. 保留完整 C/V 视图

在 CV、共享 pipe backing 规划及同步验证完成前，driver 保留配对 C/V 函数。
自动融合 VF 和前端手写 VMI/VF 进入相同的调用契约。
Cube 侧保留 TileOp 或可解析的结构化操作。

`strict_vecscope` 和显式语义边界必须保留。
普通包装作用域只有经过语义检查后才能规范化，不按固定 op 清单、文件摘要或
shape 猜测是否可删除。正式流程不能依赖 `prepare_fixture.py`。

### 4. 优化路径

```text
配对 C/V 规范化，建立逻辑 Buffer、alias 和通信事务
  → 准备可重绑定 VF，导出实际指令与资源摘要
  → 导出混合程序与优化空间
  → model/adapter 评估并返回绑定候选
  → PTOAS 生成外层调度和逐 Buffer 版本/槽位
  → PlanMemory 规划 local、pipe backing、VF scratch 与必要预留
  → 落实地址、通信与同步
  → 核对访问完成、地址复用、容量和 FIFO/依赖环
  → 导出实际编译反馈，核对或重新评估预测
  → 代码生成、独立 golden 与性能验证
```

PlanMemory 必须按完整 live-version 需求核算，不仅检查每个 allocation 的大小。
两个 AIV 分别核算私有存储，跨核共享 backing 按真实所有权核算。
借入的 pipe entry 不能被当作普通 local allocation 任意增加槽位。

复用要求所有必要访问完成，不能以调用返回、读操作已发射或模型预测时间作为
唯一安全依据。新增等待后必须重新检查依赖和 FIFO 环。
布局、同步或 lowering 增加存储需求时，重新规划并验证。
此过程有明确次数/时间预算；不能在失败 IR 上直接减槽后继续。

### 5. PlanMemory 的可验证执行

正式自动分配输入使用 level2/逻辑 allocation，不携带 local 物理地址。
报告从实际 native pass 执行中记录：规划是否执行、规划的根和槽、前后地址状态、
资源占用，以及结果与产物的共同指纹。

关闭 PlanMemory 时，无地址的活跃对象必须报错。level3 显式地址作为独立兼容模式，
不能用它替代自动分配验收。显式地址冲突必须拒绝，不能静默搬动用户指定地址。

已有地址的旧 FA 输入默认保留地址约束。另提供显式授权的重新规划策略，
仅释放已证明可重定位 local 的旧绑定；固定预留和 pinned 对象仍保留。
释放前必须恢复或校验真实 alias、ownership 和地址可观察性。
不能把相同地址直接理解为不同对象，也不能靠删除地址属性制造“自动分配通过”。
无法证明可重定位时拒绝该优化，保留合法的基线编译。

### 6. cost model 契约

沿用模型无关协议、独立进程 adapter 和现有 v1/2.0 字段语义。
prepared VF、调用效果及最终编译反馈使用独立版本和 required features 协商。
不兼容变化必须升 major，不能静默修改既有字段含义。

VF 指令、布局、配置和候选 schedule 各自绑定指纹。
cost model 评估编译器生成的 schedule，不能自行用一个 policy 数值替代编译语义。
ADR #1292 的迭代距离与交付包 `preload_depth` 分开记录，只有已证明的映射才能使用。

模型报告覆盖范围、单位和未知项。未知耗时不是 0，缺少建模能力时不能推荐。
保守求和超预算属于预检查待定，可在预算内进行真实规划试跑；超时、策略失败、
不支持和确定非法使用不同状态。

预测缓存绑定 VF、程序、bindings、target、候选、编译器、adapter、模型和配置。
最终布局或执行约束变化后，预测必须重新核对。测量缓存额外绑定设备及环境。

用户优化 annotation 继续承载 preload 和逐 Buffer 槽数。
模型排名、置信度和预测保留在外部报告。默认 annotation-only 行为保留，
正式变换通过显式 apply 模式进入。
未完成范围认证时不默认自动启用优化。

## 兼容策略与实施范围

普通编译默认流程保留。首发优化支持 A5、静态 shape、tile entry、1 AIC＋2 AIV。
覆盖静态四阶段 micro、M32 FA 的明确 Q×KV 投影与已识别状态递推。
不把 FA 的组边界或 m/l/O 状态当作互相独立的迭代。
任意动态、多轴或未知递推在未支持时明确拒绝优化，保留合法的基线编译。

首轮固定 VF 分组、layout、unroll 和核内调度配置，CV 仅搜索 preload 与合法槽数。
随后对 unroll/覆盖优化单独实验，每个 VF 配置都产生新的成本与缓存身份。

## 备选方案

- 直接移动 PlanMemory：无法保留 Tile/调用效果，也不能解决异步生命周期，拒绝。
- 继续使用固定地址脚本：保留为对照，不作为正式能力。
- 每个 CV 候选重跑全部 VF 准备：仅作调试参照；地址或布局条件改变时可重建受影响 VF。
- 初期直接新增一整套外层 IR：优先复用已有调用和分析接口，按 verifier 需求最小扩展。

## 验收含义

接口、编译合法性、数值正确性、优化收益和模型准确度分别签收。
旧固定 FA 的性能数据不替代本次自动 PlanMemory 验收。
完成定义、负例、同批新旧整链对照及 G4 门槛见实施计划。
