# 固定 FA：先选 preload、后编译的验收

日期：2026-10-27（JST）。本报告只覆盖同事提供的固定 M32 FA。
状态：固定 FA 新流程、受限 G2/G3、20 对 A/B 与独立绝对对照已完成并离线复核。

## 目的和实现

旧实验先完整编译 P0/P1/P2/P3，再让模型读取最终程序排序。
本轮将顺序改为：一次准备并融合 VF → 导出四个轻量候选 → TileSim
计时并冻结 Plan → 只完整编译选中候选 → 最终反馈重评 → 独立验收。

这是文件交换和显式优化入口的改动。复用现有原生 CV 分析/应用构造，
不在 C++ pass 内启动模型，也不重新实现 preload 排序。
新增 MultiTileBufType 的只读 C/Python 查询，以结构化方式导出槽位类型。
原有 annotation、v1/2.0 含义、普通编译和默认 annotation-only 行为保持不变。

选中候选和 P0 均启用原生 VF、实际 PlanMemory、PTOAS InsertSync/vecscope
同步和受限的完成屏障。PlanMemory 采用 disjoint 分配，不启用地址复用。
B 相对 P0 的差异是 preload 调度；本轮不能用于证明 VF 本身的收益。

## 推荐和编译顺序

| 候选 | 初选预测时延（µs） | 本轮是否完整编译 |

| P1 | 71.770584 | 是，模型推荐 |

P1/P2/P3 落在 0.5% 近似平局范围，资源相同，选择较小 P=1。
预测相对 P0 降时 24.5639%。此 P 是 #1292 的迭代距离，不等同于任意模型的 Task depth。
本轮不证明 P1 是所有候选在设备上的全局最优项。

VF 准备次数为 1；初选前设备编译为 0；正常生产路径完整候选编译为 1。
独立重放 Linux 进程构造日志和 monotonic 冻结标记通过：71 次进程启动，
14 次发生在初选之前，初选前没有 Bisheng/对象/最终 LLVM 编译。
跟踪依赖子进程保留环境，不是对抗性沙箱。

轻量分析耗时 40.5755 秒；包含准备、分析、模型初评、选中编译及重评的
在线路径共 193.6600 秒，其中选中编译及重评 137.0992 秒。
此时间不含之后的 P0 验收编译，不与历史不同环境的总编译时间计算加速比。
初选阶段 16 个独立 VF 成本条件在同一请求内各计算一次；选中后的物理重评另评估 71 个地址条件。
一次 prepare 指编译器调用次数，不是程序中只有一个 VF 函数；没有声称实现跨请求持久缓存或减少所有重评调用。

本轮只搜索 preload。完整 Plan 的 32 个分配对象均为单槽，既定 P 等版本对象已显式展开；
这不等于没有版本存储，也不代表模型进行了 multi-buffer 槽数寻优。
模型不能注入物理地址，候选设备布局由实际 PlanMemory 决定。

| 物理存储域 | 预检查及实际高水位（字节） |
| --- | ---: |
| AIC L1 / mat | 98304 |
| AIC L0A / left | 16384 |
| AIC L0B / right | 65536 |
| AIC L0C / acc | 32768 |
| 每个 AIV UB / vec | 72704 |

两个 AIV 分域核算；不把它们合并为一个 UB 预算。

## G2/G3

两份程序均通过同次编译反馈、实际地址范围、完成约束、同步覆盖和独立
静态访问/事件证据检查，得到限定于固定 FA、无地址复用的 G2。
通用编译器反馈的 evidence_incomplete 不会被偷偷升级为通用安全证明。

正式 device 1 的 G3 25/25 通过：选中候选先运行，随后六组输入、两个相反顺序各执行 A/B。
含 zero、V 全 1、Q/K/V 全 1 和三个 pattern 种子；每次重置输入及输出，
检查独立 C++/NumPy FP64 golden、输入、guard、重复结果和运行状态。
device 0 初步 G3 亦独立通过并完成本地 golden 重算，单独保留；
正式 device 1 最大绝对误差 7.9505e-6。常量 atol=1e-6，pattern atol=1e-4、rtol=1e-3。

先运行表示本实验中 B 在 A 之前、使用新符号；设备未做硬件复位，不声称冷复位验证。
